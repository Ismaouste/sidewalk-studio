## Summary

Three shell components were rebuilt on platform primitives rather than
lifecycle hooks, and two features now let the site remember a returning reader
entirely in that reader's own browser. Four pre-existing bugs surfaced while
doing it, three of them invisible until something was measured.

## Decisions

- The mobile navigation sheet and the accessibility panel are `popover`
  elements. Chosen over `<details>` because light dismiss and Escape come from
  the browser, so the keydown listener goes too. Above its breakpoint the
  navigation panel keeps the attribute and simply renders as the tab row: the
  UA's `display: none` for a closed popover is a UA-origin style, so one author
  media query outranks it and no script decides which mode the nav is in.
- No CSS anchor positioning anywhere. `db61a48` records that it was tried for
  tooltips and reverted because Chromium placed the popup wrong and never fired
  `position-try-fallbacks`. Neither new surface needs it.
- Which navigation entry is active is resolved by `PublicLocale::navigation()`.
  Sixty lines of TypeScript were reimplementing Laravel's own routing, locale
  prefixes included; two implementations of one rule only ever drift.
- The breadcrumb's stuck state is reported by a `view-timeline` on a one-pixel
  sentinel in `SiteLayout`, inset by the header height. The sentinel lives in
  the layout rather than the component because a sticky element only sticks
  within its containing block, and is out of flow because the container is a
  grid.
- Page transitions are Inertia's. The hand-rolled version called
  `startViewTransition` on `start` and held the old frame for the whole
  request, which is what its 2.2s escape hatch existed for.
- A first-ever reader is shown no "new" marks: everything being new is
  indistinguishable from nothing being new. The comparison point is frozen in
  `sessionStorage` for the visit, because the `localStorage` timestamp moves
  forward as soon as it is read.
- The resume invitation never scrolls on its own, and a reading position is
  only written between a floor and a ceiling — below the floor a revisit would
  overwrite an earned position with zero, above it the reader has finished.
- Every read and write of web storage goes through `lib/safeStorage`.

## Bugs found

- **The breadcrumb never stuck.** `overflow-x: hidden` was set on `body` as
  well as `html`; a non-`visible` value on one axis makes the other compute to
  `auto`, which turns `body` into a scroll container, so a sticky descendant
  resolves against its scrollport rather than the viewport. Measured on the
  previous commit: at scrollY 1500 the bar sat at −1340, off screen, while the
  JavaScript blurred it.
- **The site was a blank page for anyone whose browser refuses storage.**
  Reading `window.localStorage` throws rather than returning null when a
  visitor blocks site data, and the anti-flash theme script in
  `app.blade.php` read it unguarded before anything else ran.
- **CI had been red on `main` for at least three runs.** A job-level `env` in a
  GitHub workflow becomes a real environment variable and outranks
  `phpunit.xml`, so CI ran the suite against a file database that a
  `RefreshDatabase` case had already emptied. Two tests guarded their seed with
  `Schema::hasTable`, which cannot see a table that is present and empty.
- **A revisit could erase a reading position**, found by the test written for
  the feature itself.

## Follow-up

- `useAccessibilityPreferences` never seeds `data-motion` from
  `prefers-reduced-motion`, so the site's own switch and the media query
  disagree for a visitor who set neither.
- `--sw-button-primary-bg` on `--sw-button-primary-text` measures 2.95:1 in
  morning. Pre-existing, and it is the most visible button on the site.
- A link carrying `prefetch="hover"` with `cache-for` runs two full visit
  cycles when a pointer rests on it, so it crossfades twice.
- `--sw-tab-line` and `--sw-header-bg` have no consumers;
  `html[data-scroll-lock]` in `reset.css` has no writer.
- `actions/checkout@v4` and `actions/setup-node@v4` are being forced onto
  Node 24; move them to `@v5`.
