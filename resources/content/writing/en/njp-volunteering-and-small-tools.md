Some tools only make sense because a real context keeps them modest. Volunteering at Nancy Jazz Pulsations is one of those contexts for me.

## Problem

It is easy to talk about side projects as if they needed a startup-scale justification. Most do not. The more common failure is almost the opposite: a recurring annoyance exists, but nobody captures it because it feels too small to deserve a proper tool.

Volunteering helps against that reflex because the work is concrete. You see how information moves, where friction accumulates, which tasks repeat, and what people actually tolerate. That is a better design brief than a generic idea for an app.

In those environments, a useful tool does not need to look ambitious. It needs to remove one confusion, one manual loop, or one retrieval problem. That might be enough to make it worth building.

## Decision

The decision is to keep these tools intentionally narrow.

That means resisting two temptations:

- turning every small script into a platform idea;
- dismissing every small script because it is "not serious enough".

`YTMusic Liked Sorter` is a good example of that middle line. It is not tied to NJP operationally, but it comes from the same mindset: start from an actual need, keep the interface and output readable, and do not pretend the project is bigger than it is. The point is to retrieve, sort, and surface information that had become hard to revisit. Nothing more is needed for the tool to be useful.

The alternative would be to overdesign the whole thing. Add accounts, sync, dashboards, or features nobody asked for. That usually kills the charm and the clarity of a small utility. A modest tool stays good when the scope remains close to the original inconvenience it was meant to remove.

## Result

Volunteering keeps that judgment calibrated. It reminds me that software is often most helpful when it respects the scale of the context.

That lesson carries back into professional work as well. In ecommerce or content projects, not every pain point deserves a new subsystem. Sometimes the best move is still a small utility, a clearer export, a tighter data flow, or a calmer admin path. The difference is not prestige. It is fitness to the problem.
